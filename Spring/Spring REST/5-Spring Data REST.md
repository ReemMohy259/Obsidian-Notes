Spring will give you a **REST CRUD implementation for FREE** like MAGIC!!, helps to minimize boiler-plate REST code (No new coding required)

All we have to do is to add this dependency to our **POM file** (Nod coding required)
```xml
<dependency> 
	<groupId>org.springframework.boot</groupId> 
	<artifactId>spring-boot-starter-data-rest</artifactId>
</dependency> 
```
###### Internally:
* Spring Data REST will **scan** your project for **JpaRepository**
* Expose REST APIs for each **entity type** for your JpaRepository
* **By default**, Spring Data REST will create endpoints based on entity type 
	* Simple pluralized form 
	* First character of Entity type is lowercase 
	* Then just adds an "s" to the entity
##### Exposed Endpoints 
| HTTP Method | Endpoint                  | Action             |
| ----------- | ------------------------- | ------------------ |
| GET         | `/entities`               | findAll            |
| POST        | `/entities`               | create             |
| GET         | `/entities/{id}`          | findById           |
| PUT         | `/entities/{id}`          | replace            |
| PATCH       | `/entities/{id}`          | partial update     |
| DELETE      | `/entities/{id}`          | delete             |
| GET         | `/entities/search`        | list query methods |
| GET         | `/entities/search/method` | execute finder     |
| GET         | `/profile/entities`       | metadata           |

#### Configurations
We can override the default behavior of Spring Data REST to **customize** the generated endpoints
**For example:**
* Resources that don't have direct plural by only appending "s" like address -> addresses
* Change the default settings for pagination (e.g. default page size = 20)
* Change the base path for the generated endpoints (e.g. /**api**/employees)

```java
// Define your propertied inside application.xml file
spring.data.rest.base-path=/magic  
spring.data.rest.default-page-size=10
-----------------------------------------------------------
// To change the generated resource name
@RepositoryRestResource(path = "members")  
public interface EmployeeRepository extends JpaRepository<Employee, Integer> {  

}
```


> [!NOTE] Note
> If we have a controller class that annotated with `@RestController` that manually exposes the **same** endpoints generated by spring data REST, this controller has the **highest priority** over one generated by spring, so if the client request one of these endpoints **the request is served by our controller**

#### Request Flow

```
Client
   ↓
DispatcherServlet
   ↓
RepositoryRestHandlerMapping
   ↓
RepositoryEntityController
   ↓
RepositoryInvoker
   ↓
JPA Repository Proxy
   ↓
SimpleJpaRepository
   ↓
EntityManager
   ↓
Hibernate
   ↓
JDBC Driver
   ↓
Database
```

##### I. RepositoryRestHandlerMapping
Special handler mapping provided by Spring Data REST. Its job is to map repository URLs to internal controllers.
For `GET /books/1` It **detects**
- `/books`
- corresponds to `BookRepository`
- So it routes the request to `RepositoryEntityController`

> Normally in Spring MVC you **manually** define mappings. But Spring Data REST automatically generates endpoints from repositories. So `RepositoryRestHandlerMapping` **dynamically** creates mappings for repositories.

##### II. RepositoryEntityController
Internal controller used by Spring Data REST. It acts like an automatically generated REST controller.
**Responsibilities**:
- handle CRUD operations
- process REST requests
- generate HAL responses
- apply pagination
- manage relations

**Example Flow**
Client request `GET /books/1`. Internally `RepositoryEntityController    → calls repository findById()`. Then converts result into HAL JSON response.

##### III. RepositoryInvoker
Acts as a **bridge** between:
- REST layer
- Repository layer
It **dynamically** invokes repository methods.

**Responsibilities:**
- invoke repository methods dynamically
- abstract repository implementation details
- support generic repository execution

**Why RepositoryInvoker Exists**
Spring Data REST does not directly know:

```
BookRepository
AuthorRepository
CategoryRepository
```

**at compile time**. So it uses `RepositoryInvoker` to call repository methods generically. without caring about the actual repository type.

```
invokeFindById(id) 
invokeSave(entity)
invokeDelete(id)
```

#### Generated Response
Since that the controller actually uses the repository so an entity object is returned from this method and thanks to **Jackson** convert this **Java object to JSON**

**Spring Data REST responses follow:**
- **Pagination**
- **HATEOAS** (Hypermedia links)
- **HAL** JSON format **(JSON + Hypermedia Links)**
##### Example
```json
{
  "_embedded": {
    "books": [
      {
        "title": "Clean Code",
        "author": "Robert C. Martin",
        "_links": {
          "self": {
            "href": "http://localhost:8080/books/1"
          }
        }
      }
    ]
  },

  "_links": {
    "self": {
      "href": "http://localhost:8080/books"
    }
  },

  "page": {
    "size": 20,
    "totalElements": 1,
    "totalPages": 1,
    "number": 0
  }
}
```
##### Mapping Relations
Spring Data REST automatically exposes entity relationships.

**Example entities:**
```java
@Entity
public class Book{    
	@ManyToOne    
	private Category category;
}
```

**Generated response:**
```json
{
  "title": "Clean Code",

  "_links": {
    "self": {
      "href": "http://localhost:8080/books/1"
    },

    "category": {
      "href": "http://localhost:8080/books/1/category"
    }
  }
}
```

* Now the related category can be fetched using `GET /books/1/category`
