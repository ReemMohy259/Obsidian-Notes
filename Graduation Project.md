Below is the **complete Google Login flow** for your mobile developers using **Keycloak + AppAuth + Authorization Code Flow with PKCE**, where **the Keycloak login page is skipped** using `kc_idp_hint=google`.

---

# Google Login Flow

## Step 1: User clicks "Continue with Google"

```text
Mobile App

↓

Continue with Google
```

The app starts the OAuth flow using **AppAuth**.

---

# Step 2: Open the Authorization Endpoint

> **Method**

```http
GET
```

> **Endpoint**

```http
https://auth.nutriscan.com/realms/nutriscan/protocol/openid-connect/auth
```

> **Query Parameters**

|Parameter|Required|Description|
|---|---|---|
|client_id|✅|Keycloak client id (`mobile-app`)|
|redirect_uri|✅|URI that Keycloak redirects back to after authentication|
|response_type|✅|`code`|
|scope|✅|`openid profile email offline_access`|
|code_challenge|✅|Generated automatically by AppAuth|
|code_challenge_method|✅|`S256`|
|state|✅|Random value generated by AppAuth to prevent CSRF|
|nonce|✅|Random value generated by AppAuth|
|kc_idp_hint|✅|`google` (skip Keycloak login page)|

Example:

```http
GET https://auth.nutriscan.com/realms/nutriscan/protocol/openid-connect/auth
?client_id=mobile-app
&redirect_uri=nutriscan://oauth/callback
&response_type=code
&scope=openid%20profile%20email%20offline_access
&code_challenge=Jg7Xr4...
&code_challenge_method=S256
&state=8c91df...
&nonce=f3bc42...
&kc_idp_hint=google
```

---

# Step 3: Keycloak Immediately Redirects to Google

Because

```text
kc_idp_hint=google
```

is present,

the user **never sees**

```text
Keycloak Login Page
```

Instead,

```text
Keycloak

↓

Google Login
```

---

# Step 4: User Authenticates with Google

Google displays

```text
Choose an account

○ john@gmail.com

○ work@gmail.com

Use another account
```

The user signs in and grants permission.

---

# Step 5: Google Redirects Back to Keycloak

Google sends the authentication result to Keycloak.

Internally:

```text
Google

↓

Keycloak

↓

Validate Google Identity

↓

Find Existing User

or

Create New User

↓

Create Keycloak Session
```

This happens entirely on the server side.

The mobile app is **not involved** in these steps.

---

# Step 6: Keycloak Redirects Back to the Mobile App

Keycloak redirects the browser to the registered redirect URI.

Example

```text
nutriscan://oauth/callback?code=xYz123AbCdEf&state=8c91df...
```

### Redirect URI

```text
nutriscan://oauth/callback
```

This is a **custom URI scheme** that your mobile application registers.

### Android

Declare an intent filter that handles:

```text
nutriscan://oauth/callback
```

### iOS

Register the URL scheme

```text
nutriscan
```

so the application can receive the callback.

AppAuth intercepts this callback automatically.

---

# Step 7: Exchange the Authorization Code for Tokens

After receiving the authorization code, **AppAuth automatically** performs the token exchange.

> **Method**

```http
POST
```

> **Endpoint**

```http
https://auth.nutriscan.com/realms/nutriscan/protocol/openid-connect/token
```

> **Content-Type**

```http
application/x-www-form-urlencoded
```

Request Body

```text
grant_type=authorization_code

client_id=mobile-app

code=xYz123AbCdEf

redirect_uri=nutriscan://oauth/callback

code_verifier=x9PQ2...
```

> **Important**

The mobile developer **does not write this request manually**.

AppAuth sends it automatically.

---

# Step 8: Keycloak Returns Tokens

Response

```json
{
  "access_token": "eyJhbGciOiJSUzI1NiIs...",
  "refresh_token": "eyJhbGc...",
  "id_token": "eyJhbGc...",
  "expires_in": 300,
  "refresh_expires_in": 1800,
  "token_type": "Bearer",
  "scope": "openid profile email offline_access"
}
```

---

# Step 9: AppAuth Stores the Tokens

AppAuth stores:

- Access Token
    
- Refresh Token
    
- ID Token
    

The application can then call your Spring Boot APIs.

Example

```http
GET https://api.nutriscan.com/api/v1/profile
```

Header

```http
Authorization: Bearer eyJhbGciOi...
```

## Redirect URI Explained

For your project, a good redirect URI is:

```text
nutriscan://oauth/callback
```

When registering the **`mobile-app`** client in Keycloak, configure:

**Valid Redirect URIs**

```text
nutriscan://oauth/*
```

or more specifically:

```text
nutriscan://oauth/callback
```

This allows Keycloak to safely redirect the browser back to your application after authentication. AppAuth listens for this URI and resumes the authentication flow automatically.
